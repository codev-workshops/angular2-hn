# React port of Angular 2 HN

A React 19 + Vite + TypeScript port of the Angular app in the repository root. The
Angular app is untouched and remains the source of truth: every screen of this port
is verified against it pixel for pixel (see [Parity harness](#parity-harness)).

## Running

```bash
npm install
npm run dev        # http://localhost:5173  (the Angular app stays on :4200)
npm run build      # tsc -b && vite build -> dist/
npm run typecheck
npm run lint
```

The Angular app needs Node 14 (`nvm use 14`); this app uses the repository's default
Node version.

## Layout

The directory layout mirrors `src/app/` so each file can be read next to its Angular
original, and every component keeps its own `*.component.scss`.

| Angular | React |
| --- | --- |
| `app.module.ts`, `app.routes.ts`, `app.component.*` | `src/App.tsx`, `src/main.tsx`, `src/app.component.scss` |
| `core/header`, `core/footer`, `core/settings` | `src/core/…/…Component.tsx` |
| `feeds/feed`, `feeds/item` | `src/feeds/…/…Component.tsx` |
| `item-details`, `item-details/comment` | `src/item-details/…Component.tsx` (lazy) |
| `user` | `src/user/UserComponent.tsx` (lazy) |
| `shared/components/{loader,error-message}` | `src/shared/components/…` |
| `shared/services/hackernews-api.service.ts` | `src/shared/api/hackernews-api.ts` (`fetch` + `AbortSignal`) |
| `shared/services/settings.service.ts` | `src/shared/services/settings-service.ts` + `use-settings.ts` |
| `shared/pipes/comment.pipe.ts` | `src/shared/pipes/comment.ts` |
| `shared/models/*` | `src/shared/models/*` (plain interfaces) |
| `shared/scss/*`, `styles.scss` | `src/shared/scss/*`, `src/styles.scss` (copied verbatim) |

Routing mirrors `app.routes.ts` exactly, including the `/` → `/news/1` redirect, the
`:page` and `:id` params, and lazy loading of the item-details and user views.

### Angular-specific behaviour that had to be reproduced

* **Emulated view encapsulation.** Angular rewrites every component stylesheet to
  `selector[_ngcontent-xxx]` and stamps the matching attribute on the component's
  elements. Two rules copied verbatim from Angular depend on that scoping (for
  example `p` and `.title-block` rules that would otherwise leak across
  components), so `build/emulated-encapsulation.ts` is a small PostCSS plugin that
  performs the same rewrite for every `*.component.scss`, and `src/shared/scope.ts`
  supplies the `data-ng-<component>` attribute the components spread onto their
  elements.
* **Host elements.** Angular renders a host element per component (`<app-header>`,
  `<item>`, `<app-comment>`, `<router-outlet>`, …). They participate in layout, so
  the React components render the same host tags (declared in
  `src/custom-elements.d.ts`).
* **Text nodes.** Angular templates emit the surrounding whitespace of interpolated
  text as part of a single text node. The JSX writes those strings explicitly
  (`` {` ${item.title} `} ``, `{`(${item.domain})`}`) because splitting a line into
  several text nodes shifts glyph positions by a subpixel and shows up in the diff.
* **Vendor prefixes.** `.browserslistrc` is a copy of the Angular app's
  `browserslist` and `autoprefixer` runs over the same stylesheets, so both apps
  emit the same prefixed declarations.

## Deviations

Everything below is invisible in the rendered pixels; there are no visual or
behavioural deviations.

| Deviation | Reason |
| --- | --- |
| No `StrictMode` | Its development-only double render would fire every API request twice, which Angular does not do. |
| `dangerouslySetInnerHTML` instead of `[innerHTML]` | Angular's `DomSanitizer` strips nothing that the HN API returns for these fields (`<p>`, `<pre>`, `<i>`, `<a rel=nofollow>`), so both apps end up with the same DOM. Content comes from the HN API only. |
| `react-router` adds `data-discover="true"` to links; Angular dev builds add `ng-reflect-*`/`routerlink` attributes | Framework internals, no styling or layout hooks on them. Interaction assertions compare semantic state (`href`, `target`, `rel`, class names) rather than raw HTML. |
| Angular `>>>`/`::ng-deep` selectors are dropped by the PostCSS plugin | The combinator no longer exists in browsers; Angular's own compiler drops it too, so neither app applies those rules. |
| Comment collapse uses the `hidden` attribute via state | Angular's `[hidden]` binding does the same thing; both produce `hidden` on the same element. |
| `manifest.webmanifest` link omitted from `index.html` | It is generated by the Angular service-worker build and 404s in `ng serve`; the copied `manifest.json` link is kept. |
| Google Analytics snippet kept, page views sent from a route effect | Equivalent to the Angular `Router` subscription in `app.component.ts`. |
| React logs "The tag `<item>` is unrecognized in this browser" in development | Angular's `item` selector is not a valid custom-element name (no dash). Renaming it would change the DOM, so the warning is accepted. |

## Parity harness

Both apps are driven by Playwright against the **same recorded API fixtures**, with
`localStorage` seeded before navigation, so runs are deterministic and never touch
the live API. Full-page screenshots are diffed with `pixelmatch`
(`threshold: 0.1, includeAA: true`) and every case must report **0** mismatched
pixels.

```bash
# terminal 1 – Angular on :4200
source ~/.nvm/nvm.sh && nvm use 14 && npm start
# terminal 2 – React on :5173
cd react-app && npm run dev

cd react-app
npm run parity                     # 120 static cases
npm run parity -- item-story       # filter by case name
npm run parity -- --keep           # also keep PNGs of passing cases
npm run parity:interact            # 28 interaction steps across 7 flows
npm run parity:side-by-side        # labelled Angular | React composites
npm run parity:record              # re-record parity/fixtures/recorded.json
```

* `parity/cases.mjs` – the matrix: every route (feeds, pagination, empty feed, item,
  ask item, job item, poll item, user, user without an about, the error state of each
  view, and the `/` redirect) × the three themes × desktop and mobile, plus the
  settings panel per theme, non-default `titleFontSize`/`listSpacing`/
  `openLinkInNewTab`, the OS dark/light colour-scheme fallback, and the loading state.
* `parity/fixtures/recorded.json` – responses recorded from
  `https://node-hnapi.herokuapp.com`.
* `parity/fixtures/handwritten.json` – what the live API cannot serve: a poll item
  (with a nested and a deleted comment), an empty feed, and user profiles — the live
  `/user/:id` endpoint has been removed and now returns 404, which the `*-error`
  cases cover instead.
* `parity/browser.mjs` – fixture replay, `localStorage` seeding, settling, and
  freezing of animations (the loader's animation is disabled rather than sampled).
* `parity/interact.mjs` – header navigation and active-link state, pagination,
  feed → item → user navigation, the mobile back button, comment collapse/expand,
  every settings control (theme radios, new-tab checkbox, font size and list spacing
  inputs, close button) plus a reload to prove persistence, hover and keyboard focus.
  After each step the URL, `localStorage`, the asserted DOM state, and the full-page
  screenshot must match.
* `parity/css-diff.mjs` – diagnostic: dumps the CSS rules each app actually applies,
  with the encapsulation attribute normalised, to compare the PostCSS rewrite against
  the Angular compiler's output.

Screenshots of failing cases are written to `parity/screenshots/<case>/{angular,react,diff}.png`.
